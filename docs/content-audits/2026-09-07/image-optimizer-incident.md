# Broken guide images: cause and verified correction

The owner reported the ear-cleaning illustration broken after the September 7 image corrections. Both that image and the pricing-guide image were affected. Codex introduced new cache-version query strings without adding the matching `images.localPatterns` entries in `next.config.ts`.

The original PNGs returned HTTP 200, but the actual browser-facing `/_next/image` requests returned HTTP 400 `INVALID_IMAGE_OPTIMIZE_REQUEST`. An unversioned ear-cleaning request and an older allowed image query both succeeded. Next.js matches configured search strings exactly; see [the official localPatterns documentation](https://nextjs.org/docs/messages/next-image-unconfigured-localpatterns).

The earlier checks confirmed PNG availability, RGBA validity and exact source bytes. They did not request the optimized `img src/srcset` URLs generated by Next.js, so those checks missed the visible failure. This was a verification gap, not a corrupted PNG or missing upload.

## Correction

Added two exact path/query allowances for the ear-cleaning `maui-20260907-alpha2` version and pricing-guide `maui-20260907-four-limbs` version. The isolated production release changed only `next.config.ts`; all other deployed source hashes were preserved. Live deployment: `dpl_2FdtusSaohy6Tym9CvdRUBYwkysr`.

The shared publisher now parses rendered article and listing image URLs, checks mobile and desktop srcset sizes plus the src fallback, and rejects failed HTTP responses or non-image results. The strengthened check reproduced the old production failure before release. It then passed on the corrected preview and production deployments. All 17 guide-card images returned optimized HTTP 200 responses and decoded successfully. The two affected optimized images were inspected visually as served by production. Native browser automation remained unavailable; these are direct checks of the URLs emitted for browsers, not a claimed browser screenshot review.

Hermes's reviewed and installed skill now requires these checks and an exact configuration match for any versioned image URL. New guide assets should use their unique query-free filenames.

Evidence: `output/groomlocal-image-optimizer-fix-2026-09-07/` in the parent workspace, including `before.md`, `publication.json`, per-guide optimized preview/live checks, `all-guide-optimized-images.json`, and the two downloaded optimized images.
