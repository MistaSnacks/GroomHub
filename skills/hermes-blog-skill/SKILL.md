## Draft the guide

Read the live Snackbox schema with `get_schema`; use `blogPost`, Portable Text in `body`, and typed optional `sections`. See [Snackbox publication](references/snackbox-publishing.md) for the document shape. Resolve existing `author` and `guideTopic` references from the CMS. Do not invent qualifications or edit existing guides. Use the actual Pacific publication day for `date` and initial `dateModified`. Choose a nonoverlapping slug. Topic assignment is a CMS reference; no MDX file or topic-mapping code patch is needed.

Lead with a direct answer, use meaningful headings, and answer the reader's actual decision. Link prices and changing claims directly to current primary sources in the article body, not only a separate report. A provider blog describing general market prices is not its current menu; label old estimates accurately or exclude them. Do not promote a SERP snippet into verified provider pricing when the page cannot be checked. Label a small set of examples as a sample, never as a citywide or national average. Distinguish bath/tidy/full haircut, provider weight brackets, starting prices, and hourly charges. Check geography carefully: Portland, Oregon is not Portland, Maine. Use veterinary or other authoritative sources for animal-health claims and avoid diagnosis or individualized treatment advice.

### Data table

Every new guide includes at least one table in the first third of the article, directly after the opening answer, that summarizes the article's core comparison. Portable Text `body` cannot hold tables and the site renders `sections` after `body`, so structure the document this way: `body` holds only the direct opening answer (one to three short paragraphs); `sections[0]` is the table section (`heading`, `table.headings`, `table.rows`, and a `caption` with sample size, source type and month); the rest of the article follows as ordered `sections`. Do not duplicate text between `body` and `sections`. Each row must trace to a cited source or to GroomLocal's own harvested price data (`docs/price-harvest/` output from the `price-harvest` skill, which records source URL and retrieval date per price). Put the sample size and "as of" month in a caption or the sentence above the table, label starting prices as starting prices, and leave a cell blank rather than estimating it. Never present a handful of provider menus as a city or national average. If the topic has no honest tabular comparison, use a short numbered checklist instead and say so in the run report.

### Internal links

Before saving the draft, add 3 to 6 internal links and record them in the run report as `{anchor, target, reason}`:

- 1 to 2 links to the closest existing guides (from the coverage inventory), with descriptive anchors, never "click here".
- 1 to 2 links to city or service pages that match the article's geography or service (for example `/dog-grooming/wa/tacoma`, `/services/mobile-grooming`). Check that each target returns 200 and is not a filter URL with `?services=` or `?specialties=`.
- `/get-quotes` once, where the reader is ready to compare groomers.

Do not edit existing guides to add backlinks to the new one (Codex maintains them); list suggested reverse links in the report so the owner can add them. Use natural internal links to relevant existing guides, service/city pages, and `/get-quotes` where helpful. Call the section **Grooming Guides**, at `/blog`; `/resources` redirects there. Do not imply that every listing offers confirmed prices, availability, credentials, or instant booking.

### Humanize pass (required since 2026-10-04)

Unedited AI articles rarely reach position 1, and Google rates main content that is AI-generated with little added value as lowest quality (owner request, 2026-10-04). Run this pass on every new guide after the text, table and internal links are drafted and before `request_review`. Read [humanize](references/humanize.md) for the full procedure and [rewrite rules](references/humanize-rewrite-rules.md) for the style fixes. Keep all files in `<run-dir>/humanize/`.

1. Save the complete draft document JSON (`_id`, `slug`, `title`, `excerpt`, `seo`, `heroAlt`, `body`, `sections`) as `before.json` and scan it with `python3 "<skill-folder>/scripts/ai_tells.py" before.json > scan-before.txt`.
2. Value pass in `value-pass.md`: list what the top three results and People Also Ask already say, tag each section GAIN or COMMODITY, add gains only from harvested price data, a cited comparison table no top result has, sourced Pacific Northwest detail, or dated primary data, and compress commodity sections to the short answer. Aim for two or more gains; report it if fewer are possible.
3. Never write first-person experience, anecdotes, quotes, opinions or credentials for Camren, Sarah or any groomer. Write three to five interview questions for Camren instead; they go in the review note, not the body.
4. Style pass: answer first, contractions in normal prose, one hedge per claim, varied sentence length, no "X is not A; it is B" lines, no list-of-three padding, no recap ending, no em dashes. Keep every number, link, quote and source name.
5. Save the rewrite as `after.json`. `ai_tells.py --compare before.json after.json` must exit 0 (each new number needs a cited source) and `ai_tells.py after.json --gate` must exit 0 (no em dash, no model artifact, at most 3 tells per 1,000 words). Fix and re-run until both pass. Value flags such as "no first-hand experience markers" are expected here; report them, they do not block review.
6. Save `after.json` content to the CMS draft and put a before/after metrics table, the gains, the compressed sections and the questions in the run report.

## Maui artwork

Every new article requires a newly generated, topic-specific Maui illustration. Reusing or renaming a production image does not satisfy this requirement. Before generating, editing, or choosing new artwork, read the bundled [Maui style standard](references/maui/STYLE-STANDARD.md), [base prompt](references/maui/MAUI-BASE-PROMPT.md), and [image workflow](references/maui-image.md). Inspect [the approved brushing reference](references/maui/approved-reference/brushing-v2.png). The setup reference explains their canonical repository locations. These immutable September 2026 references govern appearance, not historical mascots or later generations.

Preserve Maui's face, compact four-limbed dog anatomy, burgundy outlines, cream/tan cel shading, and red MAUI bandana. Follow the canonical generation and transparent-export workflow. Save candidates and masters separately from derivatives in the run directory. Generate only in the run directory or an isolated staging copy. Generate a new scene for this article with the fixed approved appearance reference. Save the generation prompt, reference path, model/tool, opaque master if applicable, and verified transparent PNG in the run directory. Do not replace this step with an existing asset. Use the installed image helpers from an isolated staging copy when no image-generation MCP tool is exposed; inspect helper arguments before execution. Do not load a different business identity or modify credentials. For temporary setup, create a unique directory inside the run directory with tempfile.mkdtemp and retain that exact returned path. Do not delete a shared scratch path or rediscover it with find /tmp (macOS uses a symlink there). Copy only the helper, fixed reference, and prompt files that are needed; avoid copying the whole checkout. Pass existing image credentials only to the child process environment, without printing or saving their values into run artifacts. Honor image helpers' executable shebangs (including uv dependency setup), or invoke uv run --script explicitly. Do not replace that runtime with bare python3; verify required image-library imports before making a paid generation request.

Run the bundled art loop instead of hand-rolling generation and review: `python3 "<skill-folder>/scripts/maui-art-loop.py" --project-root "<checkout>" --run-dir "<run directory>" --slug <slug> --scene "<scene>" [--pose ...] [--mood ...]`. It generates a master with the checkout's `scripts/blog-hero-image.py`, has a vision model record literal observations beside the approved reference, asks TypeSafe Jev for calibrated yes/no probabilities on identity, anatomy, bandana, edges, style, scene safety, stray text and (for the export) transparency, and keeps generating with the gate's correction text until every gate reaches the threshold (default 0.85) or `--max-attempts` (default 4) runs out. On a pass it exports the RGBA derivative, runs the byte checker, gates the teal composite, writes `image-review.json` and confirms the combined checker gate. Read `art/art-loop.json`: `approved` means the artwork gate is satisfied; `exhausted` means keep the best candidate unapproved and report; `needs_export_review` means the master is fine but the transparent export needs reviewed seeds (inspect the numbered regions diagnostic, add seeds, re-run only the export). Vary Maui between posts (owner feedback 2026-09-28: recent heroes all redrew the reference, seated and facing front with a new prop beside him). Write `--scene` as what Maui is DOING with the article's props (hugging, carrying, lying beside, trotting with), never just "Maui beside X", and leave body position words out of the scene. Normally omit `--pose`: the loop rotates through a pose set that includes bipedal poses (Maui standing upright on his hind legs holding a prop, as on the apron, van and tip-jar illustrations), trotting, lying down, play bow and a three-quarter seated view, picks the pose least used by earlier runs, switches to the next pose halfway through the attempts, sends a bipedal pose example as a second reference, and records `pose_id` per attempt in `art-loop.json`. Pass `--pose` only when the article needs a specific one; apron/groomer scenes are always bipedal, so use `--pose "bipedal: standing upright on his two short hind legs, both front paws holding <prop>"`. Any pose containing "bipedal" skips the four-paws prompt guard and runs the gate in bipedal mode (raised front paws expected, at most two paws on the ground). Four-legged poses keep all paws down: the generator tends to draw a fifth limb when a paw is raised, so in that mode a raised paw is rejected, and in every mode more than four visible limbs is rejected. Maui looks at his work, not at the camera (owner feedback 2026-10-05: the 09-28 and 10-05 bipedal heroes held their props but kept the reference's front-facing grin). The loop adds a gaze rule to every prompt and runs a `gaze` gate that rejects eyes on the viewer or a copied reference face; write the scene so it is clear what he is looking at. Pass `--allow-viewer-gaze` only for a deliberate portrait. A Jev-approved image passes the visual gate. Afterwards look at the approved final yourself once. If you see a concrete defect, name it precisely (which paw, which edge, which pixels) in the run report; "possible", "may", "not independently certified" and similar hedges are not defects and must not be recorded as blockers. In review mode a Jev-approved image proceeds to the CMS draft and `request_review` regardless; the owner makes the final call in the Studio, and your note travels with the report. Never regenerate outside the loop.

Before treating an image as ready, inspect it at full size and display size on cream, teal, and dark backgrounds. Check actual alpha, intact fur interiors, readable bandana, complete props, unclipped edges, and the standard's dimensions/margins. Inspect the extractor's numbered enclosed-region diagnostic at full size and explicitly record which candidate IDs are background gaps to remove and which must stay as fur, clothing or props. Check spaces inside table supports and between arms, bodies and legs individually; transparent corners and a generic vision-tool pass do not prove those enclosed gaps are transparent. Re-extract from the preserved master with reviewed seeds when needed; this is export correction, not a new image-generation round. If no working image, vision or Jev tool is available, mark the new artwork pending and report the specific unavailable tool; never claim an unperformed visual check. Generation attempts are capped by the loop's `--max-attempts`; do not add manual rounds on top of it.
